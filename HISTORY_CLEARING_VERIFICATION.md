# Проверка сброса истории при смене режима

## ✅ Верификация выполнена

**Дата:** 8 ноября 2024

---

## 🔍 Проверяемое поведение

**Требование:** При смене режима работы бота история сообщений должна очищаться, чтобы новый режим не получал контекст от предыдущего.

**Причина:** Разные режимы используют разные системные промпты. Сохранение истории может привести к несовместимому контексту.

## 🎯 Анализ кода

### Паттерн очистки

Во всех командах переключения режима используется единый паттерн:

```kotlin
command("режим") {
    val chatId = ChatId.fromId(message.chat.id)
    val userId = message.chat.id

    // Установка флагов режима
    expertMode[userId] = false/true
    reasoningMode[userId] = "тип" / remove(userId)

    // ✅ ОЧИСТКА ИСТОРИИ
    conversationHistory.remove(userId)

    // Отправка подтверждения
    bot.sendMessage(chatId, message)
}
```

### Хранение истории

```kotlin
// TelegramBotService.kt, строка 26
private val conversationHistory = ConcurrentHashMap<Long, MutableList<Message>>()
```

История хранится в HashMap с ключом `userId (Long)`. Метод `remove(userId)` полностью удаляет запись для пользователя.

## 💡 Почему это правильно?

### Проблемы при сохранении истории

Если бы история НЕ очищалась:

```
1. User в quick_answer: "Дай быстрый ответ на задачу X"
   → Ответ: "X = 5"
   → История: [user: "задача X", assistant: "X = 5"]

2. User переключается на step_by_step
   → История сохраняется (гипотетически)
   → История: [user: "задача X", assistant: "X = 5"]

3. User: "Реши задачу Y пошагово"
   → Системный промпт: step_by_step
   → Контекст: задача X с quick_answer ответом
   → Несовместимый контекст!
   → Возможен некорректный ответ
```

### Преимущества очистки

✅ **Чистый контекст** - каждый режим начинает с нуля
✅ **Соответствие промпту** - история согласована с системным промптом
✅ **Предсказуемость** - пользователь всегда знает, что режим "чистый"
✅ **Изоляция режимов** - reasoning режимы независимы друг от друга

## 🔬 Технические детали

### Когда история НЕ очищается

История НЕ очищается при:
- Обычных сообщениях в рамках одного режима
- Использовании команды `/start` (инициализация)

### Когда история ОЧИЩАЕТСЯ

История ОЧИЩАЕТСЯ при:
- `/clear` - явный запрос пользователя
- Любом переключении режима (expert, normal, reasoning)
- Выборе любого reasoning подрежима

## 📝 Рекомендации

### Для пользователей

1. **Переключение режимов** - всегда сбрасывает контекст
2. **Многоходовые задачи** - решайте в одном режиме без переключений
3. **Эксперименты** - можно свободно переключаться без "загрязнения" контекста

### Для разработчиков

1. **Добавление новых режимов** - всегда включайте `conversationHistory.remove(userId)`
2. **Изменение логики** - если нужна опциональная очистка, добавьте флаг
3. **Тестирование** - проверяйте очистку при каждом новом режиме
